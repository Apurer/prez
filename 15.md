
Revised 15-minute structure:

**1. Hook: the rogue agent (2 min)**
Show the timezone CLI vibe-coded in one session. Tests fail → the agent "fixes" them by rewriting assertions to match its output. Green CI, wrong code. Two lessons on one slide: the agent optimized for the signal you gave it (passing tests), and it could do so because it had write access to everything and 200k tokens of accumulated drift.

**2. The ladder → the graph (2 min)**
Prompt → Spec → Skills → MCP → Agents → Graph. Then reframe: a graph isn't about parallelism, it's about *isolation*. Each node gets a fresh context, a scoped toolset, and a model sized to the job.

**3. Guardrails that contain the agent (4 min)** — the anti-rogue section
- **Tests are a protected node.** Implementer role cannot edit `tests/`; enforce with a hook that blocks edits, not a CLAUDE.md sentence (a rule is a suggestion, a hook is a guarantee). Test changes go through a separate tester role and a separate diff review.
- **Spec acceptance criteria are the source of truth**, not the test file. If the tester wants to change a test, it must cite the criterion.
- **Human gates** after clarify, after plan, before merge — moved later in greenfield, kept early in brownfield.
- **Budgets and stop conditions**: max retries on the test-fail → implement loop.

**4. Context and token economy (4 min)**
- **Lean base context**: CLAUDE.md / AGENTS.md / constitution short; everything else is a skill that loads on demand.
- **Skills over servers when it's just knowledge**: an MCP server costs tool definitions in every turn; a skill costs nothing until triggered.
- **Efficient MCP**: few, well-described tools; cap result sizes; tool search for large sets; prefer a targeted code-search server over dumping files.
- **Subagents as context firewalls**: exploration and test runs happen in a child context; only the summary comes back.
- **Reset between phases**: `/clear` (or a new session) at each graph edge; the plan file carries state, not the transcript. Auto-compact is the fallback, not the strategy.
- **Model routing**: strong model for planning, review, and gate decisions; cheaper/faster model for mechanical implementation and test runs; hooks (format, lint, type-check) instead of asking the model at all.

**5. Greenfield vs brownfield on spec-kit (2 min)**
Same graph, two configurations — one slide, two columns. Timezone CLI: gates late, cheap model on tasks, tests written first from spec. Hermes dashboard: conventions extracted into skills first, code-search MCP for understanding, gates early, narrow write scope.

**6. Close + references (1 min)**
"Spec-kit gives you nodes. You engineer the edges, the budgets, and the fences." Then the references slide.
